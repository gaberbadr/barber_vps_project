================================================================================
BLITZ.CLOUD DEPLOYMENT GUIDE (barber.devs.surf)
================================================================================
Project: Barber Management System (.NET 8 + React SPA + PostgreSQL + Redis + Nginx)
Target Domain: barber.devs.surf
Platform: Blitz.cloud (Free Plan: 512 MB Shared RAM, 10 GB Storage)

--------------------------------------------------------------------------------
STEP 1: PUSH PROJECT TO GITHUB
--------------------------------------------------------------------------------
1. Ensure your local working tree is clean and .env is not tracked:
   git status

2. Commit all configuration updates and push to your GitHub repository:
   git add .
   git commit -m "Configure Blitz.cloud deployment with edge HTTPS"
   git push origin main

--------------------------------------------------------------------------------
STEP 2: CREATE & CONFIGURE BLITZ.CLOUD APPLICATION
--------------------------------------------------------------------------------
1. Log in to the Blitz.cloud dashboard (https://dashboard.blitz.cloud/).
2. Under Account Settings -> Connected Accounts, ensure your GitHub account is linked.
3. Click "Host something new" -> "My own code".
4. Select your GitHub repository and set the branch to "main".
5. Blitz.cloud detects docker-compose.yml:
   - Application Name: barber (or preferred name)
   - Exposed Port: 80 (traffic routes through the barber-nginx reverse proxy)
   * Dashboard Verification: In the dashboard service configuration, verify that
     the public entry point is mapped to the Nginx service on port 80.

--------------------------------------------------------------------------------
STEP 3: CONFIGURE CUSTOM DOMAIN & HTTPS (barber.devs.surf)
--------------------------------------------------------------------------------
1. Add DNS Records at your domain registrar / DNS provider (Cloudflare, Namecheap):
   -----------------------------------------------------------------
   Type:   CNAME
   Name:   barber (or barber.devs.surf)
   Target: edge.blitz.cloud
   TTL:    Auto (or 300 seconds)
   -----------------------------------------------------------------
   * CRITICAL FOR CLOUDFLARE USERS: Set proxy status to "DNS Only" (Grey Cloud).
     If set to "Proxied" (Orange Cloud), Blitz.cloud cannot complete the
     Let's Encrypt ACME verification at the edge router.

2. Ownership Verification (if prompted by Blitz.cloud dashboard):
   Add a TXT record with Name: _blitz-verify.barber and the Value provided by Blitz.

3. Connect Domain in Blitz.cloud:
   - Go to your application dashboard -> "Domains" tab.
   - Click "Connect a domain" and enter: barber.devs.surf
   - Blitz.cloud provisions and manages Let's Encrypt TLS certificates at the edge.

--------------------------------------------------------------------------------
STEP 4: SET REQUIRED ENVIRONMENT VARIABLES
--------------------------------------------------------------------------------
In Blitz.cloud dashboard -> Application -> Settings -> Environment Variables,
add the following keys before deploying:

# Database Credentials
DB_PASSWORD=YourStrongDatabasePassword123!
ConnectionStrings__DefaultConnection=Host=db;Port=5432;Database=project1;Username=postgres;Password=YourStrongDatabasePassword123!

# Redis Cache (Gracefully falls back to in-memory if Redis is unavailable)
ConnectionStrings__REDIS_URL=redis:6379
CacheSettings__Redis__Enabled=true

# Security & Authentication (Generate a random 64-character secret for Key)
JWT__Key=YourLongRandom64CharacterSecretKeyGoesHere1234567890abcdefghijklm
JWT__Issuer=https://barber.devs.surf/api
JWT__Audience=project1
JWT__AccessTokenExpirationMinutes=15
JWT__RefreshTokenExpirationDays=7

# Base URLs & CORS
BaseURL=https://barber.devs.surf/api
Frontend__AllowedBaseUrls__0=http://barber.devs.surf
Frontend__AllowedBaseUrls__1=https://barber.devs.surf
DOMAIN=barber.devs.surf

# Google OAuth (Optional: required only if using Google login)
Authentication__Google__ClientId=your_google_client_id
Authentication__Google__ClientSecret=your_google_client_secret
* Note: In Google Cloud Console, add Authorized Redirect URI:
  https://barber.devs.surf/signin-google

--------------------------------------------------------------------------------
STEP 5: DEPLOY & VERIFY
--------------------------------------------------------------------------------
1. Trigger Deployment:
   Click "Deploy" in Blitz.cloud (or push to main). Monitor the "Activity / Logs" tab.

2. Verify Health Check:
   Visit: https://barber.devs.surf/health
   Expected response: HTTP 200 {"status":"Healthy",...}

3. Verify Frontend SPA:
   Visit: https://barber.devs.surf/
   Verify that the React app loads with all styling, assets, and routes.

4. Verify Backend API & Swagger:
   Visit: https://barber.devs.surf/swagger
   Verify that OpenAPI documentation loads and endpoints respond.

5. Verify Database Migrations & Seeders:
   EF Core migrations (context.Database.MigrateAsync()) and initial data seeders
   (roles, default admin, services, working hours) run automatically on boot.
   No manual SQL scripts or migration CLI commands are needed.

--------------------------------------------------------------------------------
STEP 6: REDEPLOYING AFTER NEW COMMITS
--------------------------------------------------------------------------------
1. Make local code changes and test locally.
2. Push your changes to GitHub:
   git add .
   git commit -m "Describe your update"
   git push origin main
3. Blitz.cloud detects the new commit via webhook and automatically triggers a build.
4. If auto-deploy is disabled, click "Redeploy" in the Blitz.cloud dashboard Activity tab.

--------------------------------------------------------------------------------
CRITICAL WARNINGS: STORAGE, PERSISTENCE & PLATFORM REALITIES
--------------------------------------------------------------------------------
1. Database Persistence:
   - PostgreSQL data persists in the Docker named volume "postgres_data".
   - Code redeployments and container restarts do NOT wipe named volumes.
   - Free Plan Backup Warning: Automated nightly off-site backups in Blitz.cloud
     apply only to Blitz.cloud Managed Databases, NOT custom Compose containers.
   - For automated off-site backups and dashboard pg_dump downloads, provision a
     Blitz.cloud Managed PostgreSQL instance and set DATABASE_URL in the dashboard.

2. 30-Minute Inactivity Sleep (Free Tier):
   - Free plan applications sleep after 30 minutes without visitors.
   - The first request after sleep experiences a 5–10 second cold start to wake
     containers. Automated pings do not prevent sleep on the free tier.

3. Outbound SMTP Ports Blocked:
   - Blitz.cloud firewall blocks outbound TCP ports 25, 465, and 587.
   - Direct SMTP connections (e.g. smtp.gmail.com:587) will fail/timeout.
   - Use an HTTPS REST API email provider (e.g. Resend, SendGrid) over port 443
     if sending production emails.

4. pgAdmin Accessibility:
   - Blitz.cloud provides NO SSH terminal access; SSH tunneling (ssh -L) is impossible.
   - The pgadmin service bound to 127.0.0.1:5050 cannot be reached externally.
   - To conserve RAM under the 512 MB shared budget, leave pgAdmin stopped or comment
     it out in docker-compose.yml.

--------------------------------------------------------------------------------
CRITICAL TROUBLESHOOTING
--------------------------------------------------------------------------------
- "ERR_TOO_MANY_REDIRECTS":
  Edge proxy terminates HTTPS and forwards to Nginx on port 80. Nginx passes
  X-Forwarded-Proto $forwarded_proto, and ASP.NET Core UseForwardedHeaders respects
  it. Do not add unconditional HTTP redirects inside the application.

- "SSL Certificate Not Issued / Not Secure":
  Confirm the CNAME points to edge.blitz.cloud and Cloudflare proxy is set to
  "DNS Only" (Grey Cloud). Allow up to 5 minutes for Let's Encrypt issuance.

- Backend Crashes on Startup ("502 Bad Gateway"):
  Check Blitz.cloud logs for "Startup.DatabaseInitialization". Verify that
  DB_PASSWORD in the database container matches ConnectionStrings__DefaultConnection.

- High RAM / OOM (Out Of Memory) Crashes:
  The free tier shares 512 MB across all containers. Ensure pgAdmin is disabled
  to leave maximum memory for the .NET API, PostgreSQL, and React frontend.
