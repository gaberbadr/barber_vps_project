BLITZ.CLOUD DEPLOYMENT GUIDE (barber.devs.surf)
================================================================================
Project: Barber Management System (.NET 8 + React SPA + PostgreSQL + Redis)
Target Domain: barber.devs.surf
Platform: Blitz.cloud (Free Plan: 512 MB Shared RAM, 10 GB Storage)

--------------------------------------------------------------------------------
ROOT CAUSES & ARCHITECTURAL REALITIES ON BLITZ.CLOUD
--------------------------------------------------------------------------------
1. Why visiting `/` returned the backend welcome JSON:
   - The repository previously lacked a root `Dockerfile`.
   - Blitz.cloud's AI recipe generator detected the C# project and generated a
     backend-only recipe running on port 8080.
   - The backend controller (`HomeController.cs`) had a route `[HttpGet]` at root
     `""` returning the Arabic welcome JSON.
   - Blitz routed all public traffic on `barber.devs.surf` directly to port 8080.

2. Why `db:5432` failed with "Name or service not known":
   - Blitz.cloud is a serverless container PaaS (using gVisor sandboxes), NOT a VM
     running `docker compose up`.
   - Blitz explicitly leaves out databases and dev tools (`db`, `redis`, `pgadmin`)
     declared in `docker-compose.yml`.
   - The hostname `db` does not exist in Blitz internal DNS.
   - PostgreSQL must be provisioned as a Blitz Managed Database (PostgreSQL 17),
     which injects the real connection string via `DATABASE_URL`.

3. Why Redis failed and fell back to in-memory:
   - Like PostgreSQL, the compose container `redis:6379` does not exist on Blitz.
   - The code previously only checked `ConnectionStrings:REDIS_URL` and did not
     check top-level `REDIS_URL` injected by Blitz, nor did it handle Valkey URL
     formats without usernames (`redis://:password@host:6379/0`).

4. Why "Failed to determine the https port for redirect" was logged:
   - ASP.NET Core was running behind Blitz's edge reverse proxy terminating SSL.
   - `UseHttpsRedirection()` was called without `ASPNETCORE_HTTPS_PORT=443` or
     `HttpsRedirectionOptions.HttpsPort = 443`, and `X-Forwarded-Host` was omitted
     from `ForwardedHeaders`.

5. Why frontend API requests previously failed with `/api/api/...`:
   - All frontend API calls already include `/api/` (e.g. `/api/services`).
   - `axiosInstance` defaulted `baseURL` to `/api`, causing Axios to duplicate the
     prefix to `/api/api/services`.

--------------------------------------------------------------------------------
PRODUCTION ARCHITECTURE ON BLITZ.CLOUD
--------------------------------------------------------------------------------
The repository now includes a production-grade multi-stage root `Dockerfile`:
- Stage 1: Builds the React SPA (`FrontEnd/`) with Vite into static production assets.
- Stage 2: Builds the ASP.NET Core 8 Web API (`Backend/`) in Release mode.
- Stage 3: Packages the API and places the React SPA directly into `wwwroot`.
- ASP.NET Core serves:
  * `/` and all SPA client routes (`/services`, `/booking`, `/login`, etc.) via `MapFallbackToFile("index.html")`.
  * `/api/...` for all REST API endpoints.
  * `/swagger/...` for OpenAPI documentation.
  * `/health` for platform health monitoring.
  * `/files/...` for uploaded avatars and documents.
  * `/signin-google` for Google OAuth callback.
- Total RAM footprint: ~150-180 MB (runs as 1 lean container app on Blitz).
- Easily fits in Blitz's 512 MB Free Plan alongside Managed PostgreSQL (128 MB).

--------------------------------------------------------------------------------
STEP 1: CONNECT MANAGED POSTGRESQL (barberDB)
--------------------------------------------------------------------------------
1. In Blitz.cloud dashboard (https://dashboard.blitz.cloud/databases), open your existing
   PostgreSQL database: `barberDB` (status: Ready).
2. Click the "Connect an app" button on the `barberDB` card and select your `barber` application.
   - Blitz will automatically link the database and inject `DATABASE_URL`.
   - Verification: In Application -> Settings -> Environment Variables, confirm `DATABASE_URL` is present.
   - Note: In Production, the backend requires `DATABASE_URL` and will fail fast at startup if it is missing.
     Legacy connection strings like `ConnectionStrings__DefaultConnection` are strictly ignored in production.

--------------------------------------------------------------------------------
STEP 2: VERIFY THE BLITZ.CLOUD APPLICATION
--------------------------------------------------------------------------------
1. In Blitz dashboard, open your `barber` application.
2. Verify it is connected to your repository and branch `main`.
3. Blitz detects the root `Dockerfile`:
   - Exposed Port: 8080
   - Multi-stage build compiles React SPA + .NET 8 Release
4. Under "Databases", verify `barberDB` is connected.

--------------------------------------------------------------------------------
STEP 3: CONFIGURE UPSTASH REDIS (CACHE & RATE LIMITING)
--------------------------------------------------------------------------------
Your Upstash Redis database is active and verified!
In Blitz dashboard -> Application -> Settings -> Environment Variables, add:
- `REDIS_URL`: rediss://default:YOUR_UPSTASH_TOKEN@correct-rat-169646.upstash.io:6379
- `CacheSettings__Redis__Enabled`: true

Note: The local Docker Compose Redis service has been completely removed.
Local development and production both use the distributed Upstash Redis (or in-memory if disabled).

--------------------------------------------------------------------------------
STEP 4: SET REQUIRED ENVIRONMENT VARIABLES IN BLITZ DASHBOARD
--------------------------------------------------------------------------------
In Blitz.cloud dashboard -> Application -> Settings -> Environment Variables,
add the following keys:

# Security & Authentication (Generate a strong random 64-character secret for Key)
JWT__Key=YourLongRandom64CharacterSecretKeyGoesHere1234567890abcdefghijklm
JWT__Issuer=https://barber.devs.surf/api
JWT__Audience=project1
JWT__AccessTokenExpirationMinutes=15
JWT__RefreshTokenExpirationDays=7

# Base URLs & CORS
BaseURL=https://barber.devs.surf/api
Frontend__AllowedBaseUrls__0=https://barber.devs.surf
Frontend__AllowedBaseUrls__1=http://barber.devs.surf
DOMAIN=barber.devs.surf

# HTTPS & Reverse Proxy Settings
ASPNETCORE_HTTPS_PORT=443
ASPNETCORE_ENVIRONMENT=Production

# Database: Authoritative production database URL (Injected by Blitz when linked in Step 1)
# DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/DATABASE
# (Do NOT set ConnectionStrings__DefaultConnection in Blitz dashboard; it is local-dev only)

# Redis Cache Settings
CacheSettings__Redis__Enabled=true
# (Set REDIS_URL if using Managed Redis or Upstash, or set Enabled=false if using in-memory)

# Google OAuth (Optional: required only if using Google login)
Authentication__Google__ClientId=your_google_client_id
Authentication__Google__ClientSecret=your_google_client_secret
* Google Cloud Console Authorized Redirect URI:
  https://barber.devs.surf/signin-google

--------------------------------------------------------------------------------
STEP 5: CONFIGURE CUSTOM DOMAIN & HTTPS (barber.devs.surf)
--------------------------------------------------------------------------------
1. Add DNS Record at your domain registrar / DNS provider (Cloudflare, Namecheap):
   Type:   CNAME
   Name:   barber (or barber.devs.surf)
   Target: edge.blitz.cloud
   TTL:    Auto (or 300 seconds)
   * CLOUDFLARE USERS: Set proxy status to "DNS Only" (Grey Cloud).

2. Connect Domain in Blitz.cloud:
   - Go to application dashboard -> "Domains" tab.
   - Click "Connect a domain" and enter: barber.devs.surf
   - Blitz.cloud provisions and manages Let's Encrypt certificates at the edge.

--------------------------------------------------------------------------------
STEP 6: DEPLOY & VERIFY
--------------------------------------------------------------------------------
1. Push all code changes to GitHub:

   - Backend .NET 8 Release build and publish complete.
   - Container starts on port 8080.
   - EF Core migrations (`MigrateAsync()`) and seeders run successfully on boot.

     Expected: React SPA loads (Hero section, Services, Booking UI).

   - Swagger Docs: Visit https://barber.devs.surf/swagger
     Expected: Swagger UI interactive API documentation.
   - API Metadata: Visit https://barber.devs.surf/api/info
     Expected: HTTP 200 backend info JSON.

     Expected: Handled by Google authentication middleware.

--------------------------------------------------------------------------------
LOCAL DEVELOPMENT WITH DOCKER COMPOSE
--------------------------------------------------------------------------------
For local development on your workstation with full Docker Compose:
  docker compose up --build
This will run the multi-container stack (`barber-api`, `barber-frontend`,
`barber-nginx`, `barber-postgres`, `barber-redis`) on http://localhost.
